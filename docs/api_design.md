# API Design

The API is intentionally tiny: three endpoints, one request schema, one response schema. The goal is to make the contract obvious and to keep the surface area auditable.

Base URL during local development: `http://127.0.0.1:8000`.
Interactive docs: `GET /docs` (Swagger UI generated by FastAPI).

## Endpoints

### `GET /`
Friendly project banner. Use it to confirm the service is reachable.

Response:
```json
{
  "project": "ModelWatch-GCP",
  "message": "Customer churn prediction service is up.",
  "docs_url": "/docs"
}
```

### `GET /health`
Lightweight health probe used by Cloud Run / load balancers.

Response (model present):
```json
{
  "status": "ok",
  "model_loaded": true,
  "model_version": "v1.0.0"
}
```

Response (model artifact missing on disk):
```json
{
  "status": "ok",
  "model_loaded": false,
  "model_version": "v1.0.0"
}
```

The endpoint always returns 200; the `model_loaded` flag indicates readiness. In production, configure Cloud Run's startup probe to call `/health` and pass only when `model_loaded == true`.

### `POST /predict`
Run the churn model on a single customer profile.

Request body (all fields required):
```json
{
  "tenure_months": 12,
  "monthly_charges": 75.5,
  "total_charges": 906.0,
  "contract_type": "Month-to-month",
  "internet_service": "Fiber optic",
  "support_tickets": 3,
  "payment_method": "Electronic check",
  "is_senior_citizen": 0
}
```

Validation rules (enforced by Pydantic):

| Field               | Type        | Constraints                                                |
|---------------------|-------------|------------------------------------------------------------|
| `tenure_months`     | int         | 0 ≤ x ≤ 120                                                |
| `monthly_charges`   | float       | 0 ≤ x ≤ 1000                                               |
| `total_charges`     | float       | 0 ≤ x ≤ 100000                                             |
| `contract_type`     | enum string | `Month-to-month`, `One year`, `Two year`                   |
| `internet_service`  | enum string | `DSL`, `Fiber optic`, `No`                                 |
| `support_tickets`   | int         | 0 ≤ x ≤ 100                                                |
| `payment_method`    | enum string | `Electronic check`, `Mailed check`, `Bank transfer`, `Credit card` |
| `is_senior_citizen` | int         | 0 or 1                                                     |

Success response (200):
```json
{
  "prediction": 1,
  "prediction_label": "Churn",
  "churn_probability": 0.82,
  "model_version": "v1.0.0"
}
```

## Error handling

| Status | Meaning                                  | When it happens                                |
|--------|------------------------------------------|------------------------------------------------|
| 200    | OK                                       | Successful prediction                          |
| 422    | Unprocessable Entity                     | Request body fails Pydantic validation (missing field, wrong type, out-of-range value, unknown enum value) |
| 503    | Service Unavailable                      | Model artifact is not present on disk - run `python run_training.py` |
| 400    | Bad Request                              | The model could not consume the payload (custom `ValueError` from `predict_one`) |
| 500    | Internal Server Error                    | Any unexpected exception. The handler returns `{"detail": "Internal server error"}` and never leaks tracebacks. |

422 responses follow FastAPI's standard schema:
```json
{
  "detail": [
    {
      "loc": ["body", "tenure_months"],
      "msg": "Input should be greater than or equal to 0",
      "type": "greater_than_equal"
    }
  ]
}
```

## cURL examples

Successful prediction:
```bash
curl -s -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
        "tenure_months": 36,
        "monthly_charges": 65.0,
        "total_charges": 2340.0,
        "contract_type": "One year",
        "internet_service": "DSL",
        "support_tickets": 0,
        "payment_method": "Bank transfer",
        "is_senior_citizen": 0
      }'
```

Invalid request (negative tenure):
```bash
curl -s -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"tenure_months": -5, "monthly_charges": 75.5, "total_charges": 906.0,
       "contract_type": "Month-to-month", "internet_service": "Fiber optic",
       "support_tickets": 3, "payment_method": "Electronic check",
       "is_senior_citizen": 0}'
# -> HTTP 422
```

## Versioning

The API responds with the configured `MODEL_VERSION` in the body of `/predict` and `/health`. In production, bump `MODEL_VERSION` alongside any change in the training data, preprocessing, or hyperparameters so logged predictions remain attributable.
